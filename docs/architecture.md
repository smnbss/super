## Stack

- **Language**: Node.js (ESM, `type: module`) + Bash (hooks + `bin/` wrappers) + Python (source extractors)
- **Runtime**: Node ≥ system default; auto-installs via apt-get / brew if missing
- **Distribution**: not an npm package — installed by `git clone` into `~/.super` and added to `PATH`; releases also tarred under `dist/` with `checksums.txt`
- **Skill format**: `SKILL.md` folders, portable across Claude Code / Gemini CLI / Codex CLI / Antigravity — copied into each CLI's native skills dir (Antigravity reads them natively from `.agents/skills`)

## Architecture

`super` is a Bash shim that ensures Node + dependencies, then `exec`s `node super.mjs`. The CLI has three responsibilities:

1. **Installer** (`super install`) — bootstraps the project's CLI environment. Reads `super.config.yaml` (a reference catalog), then uses each CLI's native install mechanism to:
   - Install OS prerequisites (`uv`, `bun`, `markitdown`, `ollama`, `googleworkspace-cli`, `gcloud-cli`, `gh-cli`, `playwright-cli`, `coolify-cli`)
   - Install CLI binaries (claude, gemini, codex, antigravity/`agy`)
   - Copy built-in skills from `$SUPER_HOME/skills/` into each CLI's skills dir
   - Install enabled external skills (cloned from GitHub)
   - Install enabled plugins — Claude via native `claude plugins install`; Gemini/Codex/Antigravity by flattening each plugin skill into `.agents/skills/<name>/` and copying the plugin's shared `lib/` into `.agents/lib/` so relative `../../../lib/…` imports still resolve
   - Configure enabled MCP servers, resolving `$env:VAR` references against `.env.local` (Antigravity uses `.agents/mcp_config.json` with `serverUrl` for HTTP servers); cleans stale entries from `~/.claude.json`, scoped since 2026-08 to **catalog-managed names only** (was: wiping the whole `mcpServers` object, including MCPs `super` doesn't manage)
   - `super install --skills-only` (2026-08, `db5bf88`) skips this whole configure phase — it runs only the earlier core phase (built-in skills + `.claude/skills` sync) and stops, so it cannot touch external skills/plugins/MCPs or the `~/.claude.json` cleanup above
   - Install Bash hooks into each CLI's native config dir (Claude/Codex/Gemini native shapes; Antigravity's named-hook JSON at `.agents/hooks.json` with absolute paths)
   - Scaffold `<project>/.env.local` from `references/env.example`
   - Create `AGENTS.md` plus `CLAUDE.md`/`GEMINI.md` symlinks at the project root
   - Append `SUPER_HOME` to the user's shell profile

2. **Launcher** (`super claude|gemini|codex|agy`) — launches the chosen CLI with the active session loaded, the right model/provider, and the required hooks/env. Supports `--model`, `--provider` (e.g. `ollama`), `--title`, `--resume`, `--debug`. Per-CLI management subcommands (e.g. `install`, `update`) bypass the session pipeline via the `SUBCOMMANDS` registry.

3. **Session bridge** (`super switch <cli>` / `super resume`) — maintains a Markdown session log in `sessions/YYYY-MM-DD_HHMMSS.md`. Each CLI writes its turn into the same file via session hooks; switching CLIs continues the same conversation. Files are tracked in git so sessions are portable across machines (`brain-clone`, `brain-clone-in-gcp` skills — renamed from `super-clone*` on 2026-08-29 — clone an entire workstation incl. sessions to a remote machine).

The whole tool is "one big CLI for AI coding agents" — one config to install everything, one launcher to start any CLI in a consistent environment, and one Markdown file as the source of truth for the conversation. **Antigravity (`agy`) is the notable exception in the install/hook layer**: it has no `~/.antigravity` home, requires absolute hook command paths, uses a named-hook JSON shape, and emits `serverUrl` (not `url`) for MCP HTTP servers.

**Versioning/release**: `VERSION` is the pinned source of truth; the auto-updater and banners read it. Releases are tarred into `dist/super-<version>.tar.gz` with a `checksums.txt`; `Makefile` holds the release helpers and `SAVE_AND_DEPLOY.md` documents the flow. `package.json` `version` is **not** the release authority. ⚠️ It drifted seven minors behind (`5.10.0` against `VERSION` `5.17.0` on 2026-08-12) until `443fda8` realigned it on 6.0.0, and **both read `6.7.1` as of 2026-09-04**. The rule survives the realignment: read the shipped version off `VERSION`, never off `package.json` (or off `package-lock.json`, which npm reconciles to it).

Each `bin/<name>` is a thin bash wrapper that resolves a Python interpreter and `exec`s the matching `utils/<name>.py`. `bin/pull_sources` is the orchestrator: it reads one or more manifest files, parses each non-comment line as `<tool> <args>`, resolves `<tool>` to its `bin/` wrapper, runs it, and writes `src/.last_export.json` (timestamp + success/failed counts). **15 `bin/` tools total** (14→15, `idp_to_md` added 2026-08).

Simone's call, 2026-09-09.** ⚠️⚠️ **THE EARLIER RULE IN THIS DOC — "never name a super clone by a path inside a particular brain's `github/` tree, that checkout is a local accident" — IS DELETED, NOT SUPERSEDED. It was wrong in its operative clause and it inverted the propagation direction.** ⚠️⚠️ **`~/.super` IS A SECOND, SEPARATE CLONE of the same repo and is a propagation TARGET, not the source.** ⚠️⚠️ **THE COPY OF THE SCRIPT YOU INVOKE DECIDES WHICH `skills/` TREE WINS, AND THAT IS THE WHOLE MECHANISM:** `bin/resync-vendored-skills` line 21 reads `CANON_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"` — **its own parent directory** — and `"$HOME/.super/skills"` is the **FIRST entry in that script's `CANDIDATES` list**, a destination. **So running `~/.super/bin/resync-vendored-skills` makes the stale `~/.super/skills` canonical and silently overwrites your edit.** ⚠️ **The two `bin/` scripts are BYTE-IDENTICAL (verified 2026-09-10 with `diff `~/.codex/skills/`, `~/.gemini/skills/`, and any combined `.agents/skills` tree), which are **distribution artifacts that drift from upstream**. **Patch-upstream-first rule**: fix `github/smnbss/super/skills/<skill>/` first, then run **that clone's own** `./bin/resync-vendored-skills`, then push. ⚠️ **`brain-upgrade` pulls and resyncs FROM `$SUPER_HOME`, so it propagates the
